# 安全评测产品：面试讲解

## 三分钟主线

先说需求：Agent质量不只看任务回答，还要看能不能识别风险、防护是否误伤正常任务，以及结果能否回到证据。随后打开工作台，分别展示R-Judge和G-Safeguard，不把二者混成一个榜单。

在R-Judge页，展示F1、Recall和Specificity，再打开全判unsafe的退化基线。重点说明虚警与漏报的不同代价，以及无效输出为什么不能从分母中删除。

在G-Safeguard页，展示正常／攻击×有／无防护四条件，并保留防护后失败数更高的历史观察。切换同一问题的轮次，说明回答错误、初始攻击角色和动态感染不是同一个概念。

最后把四条教学记录导入离线核算页，生成报告并下载。说明这验证的是数据契约和计分流程，不是在现场调用模型或训练GNN；真实实验、历史重算和教学样例各有标签。

## 可追问的问题

| 问题 | 需要解释的具体点 |
| --- | --- |
| 为什么整合成一个产品？ | 两种任务共享导入、指标核查、结果追溯和案例复盘流程；任务定义与分母仍独立 |
| 为什么不能只看F1？ | 类别不平衡下全判unsafe也可能很高；需要Recall、Specificity和错误方向 |
| 无效输出怎么处理？ | 先识别无效，再按官方策略计错；有效率单列，不悄悄删样本 |
| G-Safeguard为什么没有得到更好结果？ | 先陈述真实观察和协议调整，再列方法、实现、数据与随机性的候选解释；没有单一因果证据时不下结论 |
| 16题、128节点，样本量到底是多少？ | 独立单位是问题；节点与轮次相关，配对和重采样都按问题 |
| 图里红圈和填色有什么区别？ | 红圈是初始攻击者角色，填色是回答对错；二者不能替代动态感染标注 |
| 这次自己新增了什么？ | 统一产品入口、数据契约、离线核算、脱敏派生结果、导出和测试；已有论文方法不是个人新算法 |
| 能直接保护DevFlow吗？ | 当前没有接入，也未证明跨任务有效；需要定义适配场景、标注、对照和正常任务损失 |
| 后续怎样补实验？ | 固定问题级拆分与输出协议，选择一项机制或错误来源做最小对照；不在已反复诊断的旧测试题上调参后宣称新验证 |

可以把两个项目放在同一简历组合里：DevFlow体现应用与工作流，Safety Lab体现测试、评估与证据意识。不要把历史结果、AI辅助整理和独立手写贡献混为一谈。
